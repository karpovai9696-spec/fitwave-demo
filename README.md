# FitWave web app — локальный скелет (DRAFT)

FW-PHASE2-IMPLEMENT-001-LOCAL-SKELETON (commit 2).

Статический скелет без зависимостей. Без npm install, без сборщика, без сетевых вызовов, без бэкенда, без сохранения данных.

## Запуск локально

Откройте index.html напрямую в браузере или отдайте папку статически:


cd apps/web
python -m http.server 8000
# затем откройте http://localhost:8000/


## Объём

- Экраны-заглушки: landing, login, register, consent-gate, plan-home, cycle-entry, wellness-illness-entry, progress, profile-setup, plan-week, plan-session, support-list, news-list, news-article, password-recovery (все DRAFT, все макетные), плюс admin-login, admin-dashboard, admin-users, admin-exercises, admin-news, admin-support, admin-analytics (FW-PHASE2-IMPLEMENT-006; все DRAFT, все макетные, отдельная админ-навигация, админ-доступ не включён, RBAC отсутствует).
- На каждом экране виден баннер DRAFT; ничего не имеет статуса готово.
- Локальный роутер на основе хэша (FW-PHASE2-IMPLEMENT-002): канонические маршруты #/landing, #/login, #/register, #/consent-gate, #/plan-home; по умолчанию #/landing; назад/вперёд браузера через реальные записи истории. href в навигации остаются обычными файловыми ссылками для fallback без JS; роутер добавляет хэши и исправляет неизвестные/межэкранные.
- Демонстрационное состояние только в памяти и только в рамках сессии: демо-формы ничего не записывают, кроме локального для загрузки страницы демо-флага. Без localStorage/sessionStorage/indexedDB/cookies — состояние сбрасывается при навигации или перезагрузке по замыслу.
- FW-PHASE2-IMPLEMENT-008: на plan-home маршруты #/plan-week и #/plan-session рендерятся inline (без перезагрузки страницы), поэтому демо-выбор в памяти сохраняется между этими хэш-шагами в рамках одной загрузки страницы. Состояние всё ещё живёт только для этой загрузки страницы; ничего не сохраняется; перезагрузка сбрасывает всё.
- FW-PHASE2-IMPLEMENT-010: тот же inline-паттерн на cycle-entry для #/wellness-illness-entry и #/progress. Шаг progress перечисляет демо-записи только как иллюстрации и не заявляет причинно-следственной или медицинской интерпретации.
- FW-PHASE2-IMPLEMENT-011: тот же inline-паттерн на support-list для #/support-thread (inline-only хэш-маршрут; отдельного экрана support-thread.html не существует). Демо-тред — очевидно фиктивное макетное содержимое: никаких реальных имён, email, телефонов, вложений или сырых данных поддержки; отправки ответа нет; отправки уведомлений нет (CA-O7 BLOCKED); платёжного поведения нет (CA-B6 BLOCKED).

Демо записывает макетные auth-выборы в памяти; реальная аутентификация не выполняется, учётные данные не принимаются и не сохраняются, пароль не проверяется и не восстанавливается, аккаунт не создаётся, email/SMS/push не отправляются (CA-O7 BLOCKED), провайдер не подключён.

Демо записывает макетные выборы админ-модулей в памяти; реальный админ-доступ не предоставляется, RBAC не реализован и не включён, аутентификация и авторизация не выполняются, реальные пользовательские данные или PII не отображаются, содержимое поддержки не раскрывается, публикация в CMS или CRUD упражнений не выполняются, поведение платёжного, уведомительного или аналитического провайдера не подключено (CA-B6/CA-O7 BLOCKED).
- Формы — неактивные демо: ничего не отправляется, не сохраняется и не валидируется.

- Значения токенов скопированы вручную из design/tokens/colors.yaml (предложения в статусе DRAFT, ожидают браузерного аудита — CA-D3 остаётся OPEN).

## Чем это не является

Не работающий продукт. Интерфейс не заявлен готовым. Нет интеграции с провайдерами, реальных пользовательских данных, данных цикла, платёжных данных.
